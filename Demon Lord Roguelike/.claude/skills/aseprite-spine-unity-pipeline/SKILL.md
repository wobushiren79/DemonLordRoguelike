# 魔物素材从 Aseprite 到 Unity

## 确定这次从哪里做到哪里

- 从用户指令、上次交付或现有文件确认魔物、素材类别、本批款式和起止步骤。步骤编号、步骤名和具体交付物都可以用来指定范围。起止都包含在内，只指定一个具体操作时完成该步，明确要求全流程时执行第 1–5 步。用户指定步骤内的停点也有效，例如只做到已排序的 Spine 候选工程及其对比结果。
- 从起点直接读入该步所需的现有产物，核对它们属于同一魔物、同一批次和已确认的版本。向前查看已有文件只用于定位输入。某个必要产物缺失或存在多个归属不明的版本时，指出具体缺项或冲突，继续处理本批中可独立完成的部分。
- 每次进入一步前读该步的 skill 和适用的物种参考。上游链接是交接入口，终点以本次指令为准。已有同批产物时回读验证，只续做尚未完成的操作。

## 五步及交接产物

| 步骤 | 输入与执行指南 | 完成后交付 |
| --- | --- | --- |
| **1. 制作 Aseprite 子素材** | 按类别使用[装备制作](../aseprite-equipment-from-preview/SKILL.md)、[武器制作](../aseprite-weapons/SKILL.md)或[身体部件制作](../aseprite-body-parts/SKILL.md)。武器和身体部件优先补子文件对应目标层的最早空位，无空位才追加。新绘制和候选确认按对应技能执行。穿戴装备在选稿与拆件时按[披挂与双臂分层](../aseprite-equipment-from-preview/SKILL.md#披挂与双臂分层)检查。 | 已确认的子 `.aseprite`、所选款式及源帧和图层。武器同步子文件旁的武器帧名表，装备交付共用源文件、同目录的 `A<母版名>_装备.xlsx`，以及按实际装备帧号命名的效果图和参考图。 |
| **2. 回填 Aseprite 母版** | 使用已确认的子文件和选定款式，按[母版回填](../aseprite-master-backfill/SKILL.md)核对目标层、按规则补位并同步名字表。武器及身体部件在当前母版重新扫描目标层，无空位才追加。补位只补缺失的固定身体，另行核对各款源帧和目标帧。 | 正式母版和母版同级的 `<生物>_素材名字.xlsx`。交接本批名称、类别、实际母版帧号和完整图层路径。 |
| **3. 从 Aseprite 导出 Spine 分件** | 使用已确认的母版及本批帧和图层，按[分件导出](../aseprite-spine-export/SKILL.md)使用项目的 `Prepare-For-Spine_AI.lua`。 | 母版同级的 Aseprite 分件 JSON、`images/` 内的分件 PNG 和本批附件名。 |
| **4. 后台排序、重建 Spine 工程并发布** | 从原工程副本的完整骨架数据加入第 3 步的附件，绑定独立皮肤和父骨骼。按[Spine 导入流程](../spine-skin-import/SKILL.md#后台导入排序与重建)用后台 MCP 排好 Setup 槽序并生成新的候选 `.spine`。从候选回导核对槽序、骨架数据和渲染。正式发布时，验收通过后替换 Spine 母版。本次包含 Unity 导入时继续第 5 步。 | 正式发布交付验收后的 `.spine`、发布预设、同批 4.3 运行时 JSON、`.atlas.txt` 和全部 PNG 页。只试副本时交付候选、预览皮肤组合和对比结果，在第 4 步结束。 |
| **5. 导入 Unity 并同步配置** | 使用第 4 步同一批导出的完整运行时文件，按[Unity 导入](../spine-unity-import/SKILL.md)原位更新现有资源。按素材类别和名字表补齐道具、部件、多语言、图标和适用随机池，再导出受影响的 Unity 运行时配置。已有可加载的 Unity 资源时可从补表或随机池继续。 | Unity 资源与配置路径、本批皮肤和配置 ID、编辑模式验证结果。需要 Play 模式验收时由用户手动运行。 |

## 交接和续做

- 用同一份本批清单串起款式名称和类别、子文件帧号及图层、母版帧号及完整图层路径、分件附件名、Spine 皮肤全名、Unity 配置 ID。只记录已执行步骤产生的信息。子文件帧号与母版帧号分别核对。交付或暂停时列出已完成步骤、实际产物路径及接下来所需的输入。
- 第 3 步的 JSON 是送入 Spine 的分件数据，第 4 步的 JSON 是给 Unity 用的运行时骨架数据。哥布林同级目录里的 `哥布林.json` 和 `Goblin.json` 分别对应这两步，后者要与 `Goblin.atlas.txt` 和 `Goblin.png` 配套。
- 用户指定已排好顺序的 `.spine` 并只要求导出时，从第 4 步的运行时导出环节开始。核验指定文件后按[Spine 运行时导出参考](../spine-skin-import/references/mcp.md#导出运行时资源)交付配套文件。正式工程写回属于第 4 步的发布操作，按本次要求执行。
- 生图或候选款式依对应制作技能确认。Spine 候选未通过验收时，在副本上修正差异并重验。发布前如发现正式母版已有新改动，以最新母版重新核对。按各步规则保留交付物并清理临时目录与备份。

第 2 步回填史莱姆眼睛与帽子时，见[史莱姆回填规则](../aseprite-slime-backfill/SKILL.md)。哥布林武器、眼睛和嘴巴已有后续导入实例。处理尚未覆盖的组合时，以实际母版、Spine 工程和同类配置核对图层、槽、父骨骼、皮肤命名和配置归属，遇到仍不明确的规则，在相应步骤标明待补项。

例如，「哥布林已确认的眼嘴从回填做到 Aseprite 导出」执行第 2–3 步。「这份 Spine 副本已排好，继续导入 Unity」从第 4 步验收开始，完成第 5 步。「Unity 资源已导入，只补随机池」从第 5 步的随机池同步开始，完成配置导出。
