# 在 Spine 中导入角色部件、创建皮肤并导出

## 定位项目和本批素材

- 在角色 Aseprite 母版同级目录定位正式 `.spine`、[上一步生成的分件 JSON](../aseprite-spine-export/SKILL.md) 和 `images/`，从导出清单确定本批附件。以当前 `.spine` 为准，检查同类旧槽、父骨骼、绘制顺序和皮肤全名。哥布林见[哥布林参考](references/goblin.md)。
- 保持副本能解析同级 `images/`。已完成的皮肤跳过。已有同名槽或附件时，核对它的父骨骼、占位符和所属皮肤，再补缺少的步骤。分件导出可能含旧款式，按清单筛出本批，避免给旧槽额外导入默认皮肤附件。

## 后台导入、排序与重建

使用[后台 Spine MCP](references/mcp.md#连接)完成默认流程。只调整槽序时沿用现有皮肤和附件，从基准直接进入排序。只要求从指定的已排序工程导出时，直接执行[运行时导出](references/mcp.md#导出运行时资源)并核验产物。

1. 记录正式 `.spine` 的哈希，在独立目录复制工程和所需贴图。列出原工程全部骨架，从副本按[完整骨架导出设置](references/mcp.md#导出重建基准)保存基准 JSON。记录可重现当前造型的皮肤组合，保存已有导出设置和实际使用的发布预设。
2. 在完整 JSON 的工作副本上用 MCP 补入本批插槽、独立皮肤、占位符和附件。按同类槽确定父骨骼，用其设置姿态的逆变换换算附件位置与方向，尺寸取实际 PNG。若从已合并的副本续做，先回导该副本并对照原母版和本批清单，再排序。
3. 根据旧槽的前后遮挡关系，把新槽排进对应的连续区段。明确指定的槽按目标顺序排列。每次只显示一个的同类变体沿用已有组内顺序，无约定时可把新增款按编号接在同类末尾。保留其余槽的相对顺序。按[设置姿态排序与新建工程](references/mcp.md#设置姿态排序与新建工程)用 MCP 落实目标槽序，将完整数据导入新路径上的候选 `.spine`。

## 在 Spine 编辑器中导入和绑定

以下菜单步骤供用户选择手动导入、绑定皮肤或设置父骨骼时使用，从副本尚未完成的步骤继续。AI 按[后台 MCP 约定](../../memory/feedback_background_mcp.md)执行导入和回读。

1. **打开工作副本。** 在 Spine 打开本次工作目录里的 `.spine` 副本，进入设置模式（Setup），确认目标骨架和图片目录。
2. **导入数据。** 主菜单选「导入数据（Import Data）」。导入选项选「JSON 或二进制文件」，文件选母版同级刚导出的 `<母版名>.json`，缩放 `1`，关闭「新项目」，选「导入到现有骨架」并指定目标骨架。现有附件选「忽略（Ignore）」或取消「替换现有附件」，按界面显示核对后导入。核对新增插槽和附件与清单相符，旧槽和旧皮肤仍可用。 [Spine 导入指南](https://esotericsoftware.com/spine-import#Import-into-an-existing-skeleton)
3. **逐件创建皮肤并绑定。** 在同类皮肤文件夹创建与新部件同名的皮肤并激活。选中新槽下本件导入附件，执行「新建 → 皮肤占位符（New → Skin Placeholder）」，将该附件移入当前激活的皮肤。保留同类既有的插槽、占位符和附件命名约定。创建对话框出现时关闭「为每个皮肤复制附件」及相关复制选项，保持原贴图路径。一次只绑定当前皮肤对应的部件，检查其设置姿态使用对应占位符。 [Spine 皮肤占位符](https://esotericsoftware.com/spine-skins#Selected-attachments) · [皮肤文件夹](https://esotericsoftware.com/spine-skins#Folders)
4. **设置父骨骼。** 选中 `root` 下的新插槽（Slot），用「设置父级（Set Parent）」或 `P`，选择同类旧插槽所挂的已有骨骼。核对换父级后的设置姿态位置、方向和尺寸，必要时调整新附件的局部变换，使其与导入图和同类旧部件的对齐方式一致。旧附件的局部变换仅作参考。 [Spine 设置父级](https://esotericsoftware.com/spine-first-steps#Creating-bones)

## 验收与交付

1. 从候选 `.spine` 重新导出全部骨架。逐名核对实际槽序与目标序列，再以原基准和本批变更清单核对骨骼、槽属性、皮肤、附件、约束及动画。逐项验证新增部分的父骨骼、占位符、贴图、位置与跟随。槽序变化可导致骨架哈希变化。遇到清单以外的数据差异，回到工作副本修正并重新生成候选。
2. 用同一组明确指定的皮肤比对受影响动作的画面，并试切新部件。动画含绘制顺序关键帧时，按槽名核对关键帧前后的实际遮挡。重建会重置当前预览皮肤和上次导出设置，交付时附可重现造型的皮肤名称和可复用的发布预设。交付要求打开即显示特定造型时，以重新打开候选后的实际显示作为验收条件。参考[哥布林对照结果](references/goblin.md#后台排序重建实测)。
3. 从已核验的候选工程按[项目发布预设](references/mcp.md#导出运行时资源)在暂存目录导出 4.3 运行时 JSON、图集描述及全部 PNG 页，检查依赖并确认新增贴图能解析。只试副本时，交付候选和对比结果后结束。
4. 正式发布前复核母版哈希仍与起始基准一致。若其间发生变化，以最新母版重新比对和验收。验收通过后备份将覆盖的文件，以候选替换正式 `.spine`，并按本次发布范围写回同批运行时文件。核对落盘文件与已验收文件的哈希。部分写入失败时恢复本次已替换文件、移除本次新增文件。发布成功并回读后清理临时副本、备份和缓存，保留交付的预设。

需要更新 Unity 内的角色资源时，使用 [Spine 资源导入 Unity](../spine-unity-import/SKILL.md)。
