# 哥布林 Spine 部件参考

角色目录为 `../资源/生物/哥布林/`（从 Unity 项目目录定位）。以 `Goblin.spine` 的副本为基准，`哥布林.json` 是本批 Aseprite 分件输入，贴图位于 `images/`。从已验收候选按 4.3 发布预设导出同级 `Goblin.json`、`Goblin.atlas.txt` 和 `Goblin.png`，沿用预乘 Alpha、Linear 过滤和 `.atlas.txt` 扩展名。

| 本批新插槽 | 已有父骨骼 | 并入的绘制顺序区段 | 皮肤全名示例 |
|---|---|---|---|
| `Eye_11`–`Eye_14` | `Head` | 眼睛 `Eye_*` | `Eye/Eye_14` |
| `Mouth_11`–`Mouth_14` | `Head` | 嘴巴 `Mouth_*` | `Mouth/Mouth_14` |
| `Weapon_R_21`–`Weapon_R_24` | `Weapon_R`（父骨骼为 `Palm_R`） | 右手武器 `Weapon_R_*` | `Weapon/Weapon_R_24` |

- 眼睛、嘴巴、右手武器各自每次只显示一个变体。后台 MCP 把新槽排进同类旧槽的连续区段，保持各类别之间的遮挡关系。回读 JSON 时，槽序与 Spine 树从上到下的顺序相反。
- 旧骨架每款使用同名的独立插槽、皮肤占位符与附件。保留皮肤末段与插槽同名，例如 `Eye/Eye_14` 对应 `Eye_14` 槽及占位符。游戏换皮按完整皮肤名加载，再按末段定位染色用插槽。
- 导入 JSON 中的槽位于 `root`，附件坐标为相对 `root` 的设置姿态位置，宽高字段是脚本占位值。换父级后用实际 PNG 和画面对齐核验位置、方向和尺寸。`Head` 在旧设置姿态有旋转，旧眼嘴的局部角度有补偿。
- 历史增量合并试验中，Umut MCP 0.2.0 配合 Spine 4.3.26 在副本合并了表中 12 件。旧 81 槽、60 皮肤和 7 个动画的导出数据一致，新增三组槽出现在 Spine 绘制顺序列表顶部。
- 可先用 `Eye_14` 验证创建 `Eye/Eye_14` 的完整流程，再按同样方法处理其他款式。用 `Idle`、`Walk`、`Attack` 检查眼嘴随头、武器随手，以及切回旧皮肤的效果。

## 穿戴装备

- 同帧同部位共用一件皮肤。帽子主件挂 `Hat`，衣服主件挂 `Body`，裤子主件挂 `Pelvis_Base`。例如第 12 帧的 `Pants/Pants_12` 同时包含腰部和左右大小腿五个附件，各腿部附件跟随对应的 `Thigh_L/R` 或 `Calf_L/R`。袖子归同帧的 `Clothes/Clothes_*`，跟随对应的 `ArmUp_L/R`。
- 新增腿部分件按母版与身体的遮挡关系排槽。第 3 帧的右裤腿应画在右大腿前、骨盆后。验收时把身体与该帧全部装备一起合成，和母版逐像素对照；单独预览裤子看不到这处遮挡。

## 后台排序重建实测

- 另一次哥布林副本试验用 MCP 将已有的 42 个嘴巴槽排成 `Mouth_1` 至 `Mouth_42`，再导入新的 `.spine`。回导后其余 107 个槽的相对顺序一致。除目标槽序和骨架哈希，完整 JSON 逐字段相同，包含 23 根骨骼、149 个槽、128 个皮肤、149 个附件和 7 个动画。该次只测试副本。
- 原工程可见造型由 `Base/Base_1` 和 `Weapon/Weapon_R_17` 组合得到。重建后按“当前皮肤”渲染为全透明，在新工程数据上重现该组合后，7 个动画的 207 对帧逐像素一致。后续批次以当时母版的实际造型核对。
- 该次原工程的历史预设指定 JSON 4.2 并开启动画清理。实际 4.3 发布预设沿用原图集参数，使用当前 4.3 版本并关闭动画清理。从原副本导出的三份发布文件与已有资源逐字节一致，排序后的图集描述和 PNG 也一致。新工程的上次导出设置及部分导入、导出路径历史重置，发布时使用外置预设。
