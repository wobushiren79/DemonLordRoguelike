# 哥布林 Spine 部件参考

角色目录为 `../资源/生物/哥布林/`（从 Unity 项目目录定位）。在 Spine 打开 `Goblin.spine`，用 `哥布林.json` 准备导入，附件图片位于 `images/`。验收后从同一个工程导出同级 `Goblin.json`、`Goblin.atlas.txt` 和 `Goblin.png`。JSON 用 Spine 4.3 的默认设置，图集沿用工程的预乘 Alpha、Linear 过滤和 `.atlas.txt` 扩展名。

| 本批新插槽 | 已有父骨骼 | 并入的绘制顺序区段 | 皮肤全名示例 |
|---|---|---|---|
| `Eye_11`–`Eye_14` | `Head` | 眼睛 `Eye_*` | `Eye/Eye_14` |
| `Mouth_11`–`Mouth_14` | `Head` | 嘴巴 `Mouth_*` | `Mouth/Mouth_14` |
| `Weapon_R_21`–`Weapon_R_24` | `Weapon_R`（父骨骼为 `Palm_R`） | 右手武器 `Weapon_R_*` | `Weapon/Weapon_R_24` |

- 眼睛、嘴巴、右手武器各自每次只显示一个变体。用户在 Setup → Draw Order 把新旧同类槽放在一起并保存副本，组内顺序不限。AI 回读运行时 JSON 时，槽序与 Spine 树从上到下的顺序相反。
- 旧骨架每款使用同名的独立插槽、皮肤占位符与附件。保留皮肤末段与插槽同名，例如 `Eye/Eye_14` 对应 `Eye_14` 槽及占位符。游戏换皮按完整皮肤名加载，再按末段定位染色用插槽。
- 导入 JSON 中的槽位于 `root`，附件坐标为相对 `root` 的设置姿态位置，宽高字段是脚本占位值。换父级后用实际 PNG 和画面对齐核验位置、方向和尺寸。`Head` 在旧设置姿态有旋转，旧眼嘴的局部角度有补偿。
- Umut MCP 0.2.0 配合 Spine 4.3.26 在副本合并了表中 12 件。旧 81 槽、60 皮肤和 7 个动画的导出数据保持一致。增量合并后，这三组新槽在 Spine 绘制顺序列表顶部，可从那里移入表中的各自区段。
- 可先用 `Eye_14` 验证创建 `Eye/Eye_14` 的完整流程，再按同样方法处理其他款式。用 `Idle`、`Walk`、`Attack` 检查眼嘴随头、武器随手，以及切回旧皮肤的效果。
